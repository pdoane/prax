Pointer Events · 11.4.2 click

click

The click event type MUST be dispatched on the topmost event target indicated by the pointer, when the user presses down and releases the primary pointer button, or otherwise activates the pointer in a manner that simulates such an action. Pointer Events §11.4.2

Between the lines of one element

If a user mouses down on a text node child of a <p> element which has been styled with a large line-height, shifts the mouse slightly such that it is no longer over an area containing text but is still within the containing block of that <p> element (i.e., the pointer is between lines of the same text block, but not over the text node per se), then subsequently mouses up, this will likely still trigger a click event §11.4.2

Activation, and not for other buttons

In addition to being associated with pointer devices, the click event type MUST be dispatched as part of an element activation. Secondary buttons (like the middle or right button on a standard mouse) MUST NOT fire click events. §11.4.2 The page cancels the context menu over the button.
