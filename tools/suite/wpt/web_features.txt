# These rulings are tentative. They are a first classification that has not had careful review,
# and a ruling is a starting point for a decision, not the decision.
#
# The engine's ruling on each feature that web-features names
# (https://github.com/web-platform-dx/web-features), as of the version below. Each line holds the
# feature's identifier, its ruling, and the reason for the ruling where one is recorded.
#
#   build     the engine implements it, when the work of its phase reaches it
#   cut       the engine does not implement it
#   open      undecided, and not built until it is decided
#   quickjs   a feature of the JavaScript language, which the script engine provides
#
# A feature that web-features does not name, often because no engine ships it, is ruled in the
# last section once it is decided. It is named by the anchor of its definition. The rulings are a
# guide, and they change when what a feature costs or what it serves changes.
#
# Each feature is judged as docs/behavior.md describes. The engine is not a browser: its technology
# is inspired by the web and proven by running the web, and what it builds competes with a full
# browser's implementation. A feature is in scope for what it serves, the content and the native
# apps that would use it, weighed against what it costs. A Baseline feature is built unless it
# serves too little for what it costs or it is a browser product's own (automation, form filling,
# installing web apps). A feature that is useful and cheap is built though no engine ships it yet. The platform's
# integrations (payments and credentials, devices, protected media, capture, the system's
# services) are open until an embedder's need decides them.
#
# web-features 3.39.0
